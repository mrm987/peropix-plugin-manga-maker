# 레퍼런스 원본 프롬프트의 기술 구조

2026-09-14, 사용자가 제공한 `ref` 아래 PNG 25개를 PeroPix3의 `backend/meta.py:read_raw()`로 읽었습니다. 25개 모두 일반 PNG/EXIF 경로에서는 읽히지 않았지만 알파 채널의 NAI stealth 메타데이터에서 복원되었습니다. 일반 PNG 정보만 보고 프롬프트가 없다고 한 초기 판단을 정정합니다.

분석 대상은 프롬프트의 구성 문법, 좌표, 문자 처리, 수치 설정입니다. 원본 장면·대사·인물 묘사는 이 문서와 배포 파일에 포함하지 않았습니다. 모델을 훈련한 것이 아니라 작성 규칙과 프롬프트 컴파일 방식을 개선한 것입니다.

## 실제 메타데이터에서 확인한 차이

| 항목 | 첫 번째 묶음 | 두 번째 묶음 |
|---|---:|---:|
| 파일 수 | 16 | 9 |
| 베이스 길이, 문자 수 | 391~535 | 332~450 |
| 페이지당 위치 슬롯 | 2~9 | 4~8 |
| 슬롯 하나의 길이, 문자 수 | 12~468 | 17~244 |
| 슬롯에 직접 `text:`가 있는 페이지 | 13 | 0 |
| 베이스에 `teXt:`가 있는 페이지 | 1 | 9 |
| 슬롯에 큰따옴표가 있는 페이지 | 1 | 9 |
| 호스트 텍스트 조립 규칙으로 베이스의 자동 블록이 재구성되는 페이지 | 1 | 9 |

모든 파일에서 `v4_prompt.use_coords=true`, `use_order=true`이며, 각 슬롯의 `centers`에 자유 좌표가 들어 있습니다. V5에서도 페이로드 필드 이름에 `v4_prompt`가 쓰인다는 점과 모델 버전 자체는 구분해야 합니다.

검사한 `Panel 1`/`Scene 1` 같은 번호 표기, `four panels` 같은 개수 표현, `top-left` 같은 위치 표현은 발견되지 않았습니다. 베이스 전체를 긴 컷별 설명으로 구성하는 방식과 차이가 있습니다. `comic`, `manga`, `monochrome` 등 전역 태그에 짧은 지역 프롬프트와 좌표를 결합하는 구조입니다. 검사한 표현이 없다는 사실이 모든 종류의 구도 지시가 없다는 뜻은 아닙니다.

베이스의 `1girl, 1boy` 같은 인원 태그와 위치 슬롯 수는 일치하지 않습니다. 같은 인물의 여러 등장, 배경·물체, 말풍선과 내레이션에 슬롯을 쓰는 구조로 해석할 수 있습니다. 따라서 **캐릭터 슬롯 하나를 반드시 고유 인물 한 명이나 컷 하나와 동일시하면 안 됩니다.**

## 대사에는 두 경로가 있다

첫 번째 묶음은 캐릭터 슬롯이나 독립 문자 슬롯 끝에 소문자 `text:`를 직접 적는 경우가 많습니다. `narration box`, `speech bubble`, `text box`를 포함한 별도 좌표 슬롯도 확인됩니다. 문자도 위치를 갖는 요소로 다루는 방식입니다.

두 번째 묶음은 슬롯 안에서 말풍선과 따옴표 대사를 설명하고 베이스 끝에 `teXt:`로 문자를 모읍니다. 9개 모두 호스트의 `naitext.strip()`이 슬롯의 따옴표·좌표로 같은 자동 블록을 재구성해 제거했습니다. 이 대소문자 표기는 별도의 마법 태그로 보기보다 웹 클라이언트의 자동 문자 조립 결과와 일치하는 표식입니다.

[NovelAI 텍스트 문서](https://docs.novelai.net/en/image/textrendering/)도 베이스 끝의 `Text:`와 자연어 문자 설명을 함께 쓰는 방법, 캐릭터 프롬프트에 문자 블록을 넣는 방법을 설명합니다. 플러그인은 1.0.7까지 명시적인 `Text:` 블록을 직접 조립했으나, 1.0.8부터는 두 번째 묶음과 같은 방식으로 따옴표 대사만 두고 호스트의 자동 조립에 맡깁니다.

## 가중치와 생성 설정

첫 묶음에는 `0.8::`, `3::`, `-6::` 같은 수치 가중치와 중괄호·대괄호 문법이 있습니다. 두 번째 묶음은 대체로 그보다 단순하며 일부 슬롯에 가중치가 있습니다. **특정 값이 만화 품질의 원인이라는 비교 실험은 없습니다.** 대상 태그와 모델 반응을 확인하지 않고 강한 음수 가중치를 공통 기본값으로 복사하지 않았습니다.

25개 모두 저장 설정은 832×1216, 28 steps, CFG 6, Karras입니다. 샘플러는 Euler ancestral 19개, Euler 4개, DPM++ 계열 2개입니다. CFG rescale은 첫 묶음 0, 두 번째 묶음 0.4입니다. 이는 표본의 설정 기록이며 최적값이라는 증거가 아닙니다.

1.0.4의 생성 옵션 가져오기로 원본 25장을 다시 확인했습니다. CFG·리스케일·스텝·생성 해상도를 모두 읽었고, 지원하지 않아 제외된 옵션은 없었습니다. **1.0.5부터는 사용자 요청에 따라 해상도를 복사하지 않습니다.** 만화 기본 해상도는 832×1216이며 사용자가 직접 설정한 페이지 크기를 유지합니다.

요청 종류는 `PromptGenerateRequest` 17개, `NativeInfillingRequest` 7개, `Img2ImgRequest` 1개입니다. 일부 결과에는 수정 생성 과정이 반영되어 있으므로 한 번의 텍스트 생성만으로 같은 완성도를 얻었다고 단정할 수 없습니다. 첫 묶음의 파일 크기는 1664×2432로 저장 생성 크기의 두 배지만, 그 사실만으로 후처리 과정을 전부 복원할 수는 없습니다.

두 번째 묶음의 네거티브에는 `screentone`도 있습니다. 흑백 만화에 스크린톤을 항상 강제해야 한다는 근거로 쓸 수 없습니다. 작화 취향에 따른 네거티브와 공통적인 만화 구성법은 별개입니다.

## 1.1.0 재분석: 레퍼런스는 문장을 쓰지 않는다

2026-09-14 저녁, 같은 25장을 다시 집계했다. 베이스에 영어 문장이 있는 페이지 0/25, `panel`·`page`·`read` 낱말 0/25. `comic` 25/25, `dynamic angle` 25/25, `multiple views` 23/25, `monochrome` 24/25, `screentones` 15/25, `hatching (texture)` 15/25, `best illustration`·`novel illustration`·`high complexity` 16/25, 장소 태그(`indoors` 등) 18/25. 슬롯 131개는 전부 태그만이고(문장 0), 첫 태그는 `girl`/`boy`/`no humans`, 그 다음이 카메라 태그(`from side` 24, `face focus` 17, `from above` 14, `profile` 14, `full body` 12, `from behind` 11, `upper body` 9)다. 작은 컷은 `small panels`(4)·`inset panels`(3) 태그로 표시한다. 길이 중앙값 134자.

1.0.x 컴파일러는 베이스에 페이지 구성 문장·읽는 방향 문장을, 슬롯에 "Panel N, top right only"와 장면 문장을 넣었고 `multiple views`·`dynamic angle`이 없었다. 1.1.0은 이 집계대로 태그만 쓰는 형식으로 바꿨다(`core.compile_page`, README 「레퍼런스 형식의 프롬프트」).

## 플러그인에 반영한 방식 (1.0.x, 기록)

새 만화의 「좌표 중심」 모드:

1. 베이스에는 화풍, 페이지 개수·읽는 방향, 고유 인물 수와 전체 문자 블록을 둡니다.
2. 같은 인물도 컷마다 별도 슬롯으로 만들고 공통 외형을 반복합니다.
3. 장면·카메라·동작과 말풍선 설명은 그 인물의 위치 슬롯에 둡니다.
4. 내레이션은 컷 상단에 별도 좌표 슬롯으로 배치합니다. 이 슬롯도 페이지당 22개 예산에 포함합니다.
5. LLM은 한 컷에 한 순간을 담고, 화면 거리와 각도를 구분하며, 대사를 위한 여백을 계획합니다.

다음은 원문을 재현하지 않은 중립적인 구조 예시입니다.

```text
Base:
comic, manga, monochrome, 1girl, 1boy.
A complete 2-panel comic page. Read top to bottom.
Text: 傘、ありがとう。

Position slot (0.30, 0.25):
girl, short brown hair, yellow raincoat. Medium shot, holding a closed umbrella.
A speech bubble with its tail pointing to this character reads "傘、ありがとう。".

Position slot (0.70, 0.27):
boy, short black hair, blue jacket. Medium shot, smiling at the other person.
```

기존 「상세 지시」 모드도 유지합니다. 기존 프로젝트에서 프롬프트 모드가 저장되어 있지 않으면 상세 지시로 해석합니다. 1.0.2의 자유 배치+좌표 중심 모드는 컷 번호와 동일한 테두리 강제 문구를 빼고 전체 구성 설명 및 지역 슬롯을 사용합니다. 상세 지시 모드는 편집한 영역과 컷을 대응시키는 번호·경계를 덧붙입니다.

1.0.1에는 최대 4컷 기본값과 고정 템플릿이라는 제약이 남아 있었습니다. 1.0.2에서 컷 수 자동(1~12), 컷마다 자유로운 위치·크기, 사선·겹침·테두리 없는 영역을 지원하도록 스키마와 편집기를 변경했습니다. 사선은 제작기가 정의한 두 기울기를 사용하며 임의의 모든 다각형을 지원하는 것은 아닙니다. 이 영역들은 NAI에 보내는 구도 지시와 좌표 계산에 쓰이며 픽셀을 마스킹하지 않습니다.

두 방식의 실제 이미지 품질 비교는 아직 하지 않았습니다. 레퍼런스의 프롬프트 구조를 읽었다는 사실과 새 컴파일러가 같은 품질을 보장한다는 주장은 구분합니다.
