# 만화 제작기 (PeroPix 3.0 플러그인)

짧은 줄거리를 입력하면 선택한 CLI 또는 API LLM이 페이지 수, 기승전결, 캐릭터 외형, 컷 배치와 대사를 정합니다. 각 페이지를 NAI V5의 베이스 프롬프트와 **위치를 지정한 캐릭터 프롬프트**로 바꾸어 생성합니다.

## 설치와 실행

PeroPix 의 **플러그인 → 관리 → 플러그인 목록**에서 「만화 제작기」를 설치합니다. 설치가 끝나면 앱을 다시 실행하고 플러그인 화면에서 엽니다.

직접 넣으려면 이 저장소를 받아 앱 루트의 `plugins/manga-maker/` 에 풀고 앱을 다시 실행합니다. 별도의 pip/npm 설치나 빌드는 필요 없습니다. 플러그인은 PeroPix 의 FastAPI, Pydantic, LLM 중계, NAI 요청 조립기와 생성 큐를 사용합니다.

1. 「만화 기획 LLM」에서 Claude Code CLI, Codex CLI 또는 API 공급자를 선택하고 모델과 추론 강도를 고른 뒤 저장합니다. CLI는 설치와 기존 CLI 로그인이 필요하며 별도 API 키가 필요 없습니다. API 공급자의 키는 PeroPix AI 조수 설정에 등록합니다. 이미지용 NAI 계정도 앱 설정에서 등록합니다.
2. 스토리를 적습니다. 「예시 넣기」로 마린이 고죠의 집에 놀러 가는 줄거리를 넣을 수 있습니다.
3. 페이지 수(자동 또는 1~8, 이어서 그리기로 40장까지), 최대 컷 수(자동 또는 1~12), 자유 배치/고정 템플릿, 흑백/컬러, 읽는 방향, 대사 언어를 고릅니다. 새 만화는 자유 배치와 컷 수 자동이 기본입니다. 자동은 페이지마다 이야기와 호흡에 맞춰 컷 수를 정하며, 최대값을 채우라는 지시가 아닙니다.
4. 「AI로 기획하기」는 콘티까지만 만듭니다. 「기획부터 이미지 생성까지」는 선택한 워크스페이스·NAI 계정으로 이미지까지 순서대로 생성합니다.
5. 콘티에서 인물의 점을 끌어 옮기거나 수치로 위치를 조정합니다. 자유 배치는 컷 자체의 위치·너비·높이와 테두리도 편집합니다. 컷의 장면·카메라·동작·대사, 공통 캐릭터 외형을 수정할 수 있습니다. 수정 내용은 자동 저장됩니다.
6. 「이 페이지 생성」은 선택한 페이지를 생성하거나 재생성합니다. 「남은 페이지 생성」은 아직 결과가 없는 페이지만 생성합니다. 이미 만든 페이지를 수정한 경우에는 해당 페이지의 생성 버튼을 누릅니다.
7. 「생성 이미지」에서 원본과 이전 버전을 봅니다. 「ZIP 저장」은 기획 JSON, 실제 프롬프트와 보관된 모든 이미지 버전을 묶습니다.

페이지 수·스토리는 기존 프로젝트에서도 수정할 수 있습니다. 이야기를 고쳐 적고 「이 이야기로 전체 다시 기획」을 누르면 현재 프로젝트의 콘티를 처음부터 만듭니다. 완료되면 새 기획으로 교체하고, 이전 이야기·기획·모든 이미지 버전은 상단 프로젝트 목록의 「[이전 기획]」에 보관합니다. 실패하거나 중단하면 이전 기획으로 돌아갑니다. 앱이 전체 재기획 도중 종료되어도 이전 기획을 복원합니다.

각 페이지의 「이 페이지 재기획 지시」에 원하는 수정 내용을 적고 「이 페이지 다시 기획」을 누르세요. 예를 들어 마지막 장면을 크게 하거나, 특정 컷을 줄이거나, 대사를 바꾸도록 요청할 수 있습니다. 빈칸이면 현재 설정으로 다시 구성합니다. 입력한 지시는 페이지를 오가거나 중단해도 열린 창에 남습니다.

「새 만화」는 별개의 프로젝트를 시작합니다. 「기획 이어서」는 현재 저장된 기획에서 남은 페이지를 구성합니다. 대사 언어도 기존 프로젝트에서 변경할 수 있습니다.

## 콘티를 한 번에 짭니다 (1.7.0)

콘티를 페이지마다 따로 묻지 않고 남은 페이지를 한 번에 묻습니다. 처음 기획은 8페이지까지, 이어서 그리기도 한 번에 8페이지까지라 언제나 한 번의 요청입니다.

페이지마다 물으면 매 요청이 새 대화여서 지시문·스키마·이야기·캐릭터 설정·앞 페이지를 처음부터 다시 따졌고, 그 되풀이되는 추론이 시간을 거의 다 먹었습니다. 2026-09-21 실측입니다(opus, xhigh, 6페이지).

| | 한 장씩 여섯 번 | 한 번에 여섯 장 |
|---|---|---|
| 걸린 시간 | 17.1분 | 6.4분 |
| 출력 토큰 | 72,486 | 31,606 |
| 비용 | 약 $2.5 | $0.85 |

시간은 출력 토큰 수에 그대로 비례했습니다(측정 세 건 모두 초당 73~82토큰). 한 장을 뽑을 때 출력 12,081토큰 중 실제 답은 1,000토큰쯤이고 나머지는 추론이며, 그 추론의 상당 부분이 페이지마다 다시 할 필요가 없는 밑작업이었습니다. 같은 밑그림으로 만든 결과는 스키마와 검증을 여섯 장 모두 통과했고, 사각형이 아닌 컷이 25컷 중 4컷에서 23컷 중 9컷으로 늘었습니다.

- 진행 표시는 페이지별로 오르지 않습니다. 「N페이지 컷과 캐릭터 프롬프트 구성 중」과 경과 시간만 나옵니다.
- 「기획되는 대로 생성」이 기획과 겹치는 것은 이어서 그리기뿐입니다. 처음 기획은 페이지가 한꺼번에 나오므로 다 나온 뒤에 생성이 시작됩니다.
- **출력이 중간에 끊겨도 온 만큼은 저장합니다.** 끝이 잘려 통째로는 못 읽는 응답에서도 완결된 페이지만 골라 남깁니다. 다시 묻지 않습니다. 다시 묻는 것은 처음부터 다시 출력시키는 일이라, 이미 만들어 둔 페이지까지 함께 버리게 됩니다.
- 못 받은 페이지는 페이지 줄에 「출력 중단」으로 서고, 그 자리에서 지울 수 있습니다. 그대로 두고 「콘티만」을 누르면 그 페이지부터 이어서 짭니다. 지울지 이어 짤지는 보고 정하시면 됩니다.
- Anthropic 직결 API 는 출력 상한을 요구해서 앱이 32,000을 기본으로 넣습니다. 8페이지면 그 값에 걸리므로 콘티 요청에만 64,000을 실어 보냅니다. CLI 와 나머지 공급자는 상한을 보내지 않습니다.

## 컷 안을 캐릭터 프롬프트 블록으로 (1.5.0)

컷 하나의 편집창은 인물 줄과 대사 줄이 따로 놓인 평평한 목록이었습니다. 어느 대사가 어느 인물의 프롬프트에 들어가는지 보이지 않았고, 내레이션은 독립된 캐릭터 프롬프트인데도 대사와 같은 줄로 서서 번호가 없었습니다.

- **블록 하나가 캐릭터 프롬프트 하나입니다.** 인물 블록·내레이션 블록·인물 없는 컷의 블록이 컷 안에 차례로 서고, 왼쪽 세로선의 색이 콘티 표식의 색과 같습니다.
- **인물의 대사는 그 인물 블록 안에 들어갑니다.** 같은 번호에 묶인다는 것이 보입니다. 대사의 화자를 바꾸면 그 대사가 상대 인물의 블록으로 옮겨 갑니다.
- **내레이션은 자기 블록으로 추가됩니다.** 화자 선택의 한 항목이 아니라 「내레이션 추가」로 넣습니다. 그래서 화자 목록에는 그 컷의 인물만 남습니다.
- **「대사 추가」는 인물 블록 안에 있습니다.** 누른 그 인물의 대사로 붙습니다. 컷 아래에는 「인물 추가」와 「내레이션 추가」가 남습니다. 편집창에서 인물을 넣고 빼는 것은 이번이 처음이며, 인물을 뺄 때 그 인물의 대사가 있으면 앱 확인창으로 묻습니다.
- **내레이션도 콘티에서 끌어 옮깁니다.** 그러면서 자리를 들고 있게 되어, 내레이션을 하나 더 넣어도 이미 놓인 것이 밀리지 않습니다. 자리를 정하지 않은 내레이션은 예전처럼 컷 위쪽에 읽는 순서대로 나뉘어 놓입니다.
- **번호 배지가 콘티의 표식과 같은 모양입니다.** 인물은 그 인물 색 동그라미, 내레이션과 인물 없는 컷은 중립색 둥근 사각형입니다. 편집창과 「실제 NAI 프롬프트」가 같은 배지를 씁니다.
- **동작 태그를 비울 수 있습니다.** 스키마가 한 글자 이상을 요구하던 것을 풀었습니다. 컴파일러는 이미 빈 값을 걸러 내므로 프롬프트에는 아무것도 남지 않습니다.
- **공통 캐릭터 설정이 「장면 태그」 바로 아래로 올라왔습니다.** 페이지 전체에 걸리는 값끼리 모입니다.
- **컷은 번호 칩으로 골라 하나만 폅니다.** 컷을 세로로 쌓으면 하나를 고치는 동안 나머지가 화면을 다 차지했습니다. 페이지마다 어느 컷을 보고 있었는지 기억합니다.
- **고른 컷은 콘티에서도 강조됩니다.** 옅은 강조색 바탕과 강조색 테두리입니다. 테두리 없는 컷은 선이 없으므로 그 컷만 점선으로 두릅니다.
- **컷 안 위치는 콘티에서 끌어서만 정합니다.** 숫자 두 칸을 걷어냈습니다. 내레이션도 이미 끌기뿐이라 방법이 하나로 모입니다.
- **콘티 너비가 스크롤에 흔들리지 않습니다.** 콘티와 편집창이 같은 칸 안에서 구르던 탓에, 컷이 길어져 스크롤바가 생기면 그 10px 이 두 칸에 나뉘어 콘티가 5.66px 씩 줄었습니다. 스크롤바 자리를 늘 비워 두어 내용 길이와 무관하게 같은 너비를 씁니다.

## 콘티가 캐릭터 프롬프트를 번호와 색으로 보여 줍니다 (1.4.0)

한 페이지는 베이스 프롬프트 하나와 **캐릭터 프롬프트 여러 개**로 컴파일되고, 그 하나하나에 페이지 안의 좌표가 붙습니다. 「실제 NAI 프롬프트」에는 1번부터 번호가 붙어 있었지만, 콘티는 컷 안에서만 세는 다른 번호를 보여 주어 둘을 맞춰 볼 수 없었습니다.

- **콘티의 번호가 캐릭터 프롬프트의 번호입니다.** NAI 에 실리는 차례 그대로이며, 편집창의 인물 줄과 「실제 NAI 프롬프트」 목록이 같은 번호를 씁니다.
- **인물마다 색이 다릅니다.** 같은 인물은 어느 컷에서나 같은 색이라, 페이지를 훑으면 누가 어디에 있는지 한눈에 보입니다.
- **인물이 아닌 칸은 중립색입니다.** 내레이션 상자와 인물 없는 컷이 그렇습니다. 이 둘은 자리를 코드가 정하므로 끌어 옮길 수 없고, 모서리가 둥근 사각형으로 그려 인물의 동그라미와 구분합니다.
- **용어를 NAI 에 맞췄습니다** — 「위치 프롬프트」가 아니라 「캐릭터 프롬프트」입니다. 위치는 그 프롬프트에 지정하는 값입니다.
- **고정 템플릿의 읽는 순서를 서버와 맞췄습니다.** 콘티가 쓰던 정렬은 세로로 긴 칸을 다른 칸들 사이에 끼워 넣어, 보여 주는 자리와 실제로 생성되는 자리가 어긋났습니다.

## 앱과 같은 화면으로 (1.3.0)

이 플러그인은 시험용으로 시작해 제 스타일을 따로 짜 두었고, 그래서 PeroPix 본체의 규약과 여러 곳에서 어긋나 있었습니다. 공통 자산(`/plug/_app/base.css`·`peropix.js`)이 주는 것을 쓰도록 고쳤습니다.

- **확인창을 앱이 그립니다.** 페이지 삭제와 화풍 삭제는 `peropix.ask()` 로 앱의 확인창을 부릅니다. 새 화풍의 이름은 제자리 입력칸으로 받습니다. 브라우저 `confirm`·`prompt` 는 앱 밖 OS 대화상자라 앱의 글꼴·테마·언어와 따로 놀고, 장식 없는 창에서는 엉뚱한 자리에 떴습니다.
- **세 언어를 지원합니다.** 화면 문구와 백엔드가 보내는 상태 글까지 앱 언어를 따라갑니다(`web/i18n.js`). 앱 설정에서 언어를 바꾸면 새로고침 없이 따라옵니다.
- **앱 설정의 글자 크기를 따라갑니다.** `font-size` 를 px 로 박아 두었던 열 곳을 글자 토큰으로 바꿨습니다.
- **다크 테마에서 강조 글자가 또렷합니다.** 글자에 쓰던 `--accent` 를 `--accent-ink` 로 바꿨습니다. `--panel` 위 대비가 3.7:1 에서 8.6:1 이 됩니다.
- **제목을 한 번만 답니다.** 창틀이 이미 「만화 제작기」를 달고 있어 페이지 안의 제목과 표어를 걷었습니다.
- **할 일을 알려 주는 문구를 걷었습니다.** 화면에 남는 줄은 지금 상태를 말하는 것뿐입니다.
- **저장 버튼이 없습니다.** 자동 저장만 남았습니다. 실패는 위쪽 경고 띠가 말합니다.
- **설정 패널은 가장자리 손잡이로 접습니다** (앱의 좌우 패널과 같은 자리).
- **면이 두 겹입니다.** 기둥과 틀은 가라앉은 톤, 그 위의 상자만 밝은 톤입니다. 콘티 무대는 들여다보는 자리라 가라앉은 톤에 1px 테두리를 둡니다.
- **창 높이 셈을 공통 골격에 맡깁니다.** 머리 높이를 `calc(100vh - 78px)` 로 박아 두어, 창이 좁아 머리가 두 줄이 되면 왼쪽 패널 높이가 어긋났습니다.
- **기본 창 크기를 1080 × 760 으로 줄였습니다.** 1440 × 900 은 앱 기본 창에 들어가지 않아 처음 열 때 오른쪽이 잘렸습니다.

## 세로로 긴 컷 (1.2.0)

고정 템플릿이 가로띠와 격자뿐이라 세로로 긴 컷을 만들 수 없었습니다. 셋을 더했습니다.

- **좌우 두 컷** (`two-cols`) — 페이지를 좌우로 가른 세로 컷 두 개
- **세로 컷 왼쪽** (`tall-left`) — 왼쪽에 세로로 긴 한 컷, 오른쪽에 위아래 두 컷
- **세로 컷 오른쪽** (`tall-right`) — 그 거울

읽는 순서는 자유 배치가 쓰던 판정(`core.reading_order`)을 그대로 씁니다. 세로로 긴 칸은 여러 줄에 걸치므로 `y` 부터 줄을 세우면 다른 칸들 사이에 끼어 들어가는데, 그 방식을 걷어냈습니다. 가로띠와 격자만 있던 옛 여덟 템플릿은 두 방식의 결과가 같아 그대로입니다.

자유 배치 지시문에도 높이가 필요한 장면에서 세로로 긴 컷을 쓰라는 문구를 넣었습니다.

## 참고 이미지의 화풍과 네거티브 (1.0.3)

「참고 이미지와 화풍 → 참고 이미지 가져오기」에 PNG/JPEG/WebP를 선택하거나 끌어 놓습니다. 호스트의 메타데이터 리더가 PNG 정보, EXIF, 알파 채널의 숨겨진 NAI 정보까지 읽습니다. 원본 프롬프트가 남아 있는 이미지가 필요하며 파일은 32MB까지 받습니다.

선택한 만화 전용 LLM이 원본 베이스·캐릭터 프롬프트에서 작가·작화·선·매체·채색·품질 등 재사용할 화풍 태그를 분리합니다. 인물·의상·장면·대사·컷 배치는 제외하도록 지시합니다. 베이스 네거티브는 프리셋 문자열까지 포함해 그대로 가져옵니다. 캐릭터별 네거티브를 다른 인물의 전역 네거티브로 복사하지 않습니다.

가져온 값은 「공통 화풍 프롬프트」와 「공통 네거티브 프롬프트」에서 직접 수정합니다. 화풍 프롬프트가 차 있으면 그것이 기본 흑백/컬러·품질 태그를 대신하므로 서로 다른 화풍 태그가 섞이지 않습니다. 비우면 「구성 → 그림」의 흑백/컬러 기본 태그로 돌아갑니다. 네거티브는 별도로 편집한 값을 계속 사용하며 빈 칸도 그대로 반영합니다.

참고 이미지의 베이스 네거티브에 `no text`, `comic` 등 원하는 표현을 억제하는 항목이 있다면 편집할 수 있습니다. 실패하면 적용 중인 화풍을 교체하지 않습니다. 프로젝트에는 추출된 태그·네거티브·참고 파일명이 저장됩니다. 이미지 픽셀을 NAI 참조 이미지로 전송하는 기능과는 별개입니다. 화풍 추출에는 선택한 LLM의 사용량이 적용됩니다.

## 내 화풍 저장과 관리 (1.0.7)

참고 이미지에서 화풍을 추출하면 「화풍 → 내 화풍」에 자동 저장됩니다. 기본 이름은 이미지 파일명입니다. 다음부터는 목록에서 고르기만 하면 이미지 업로드나 LLM 재호출 없이 그대로 적용됩니다. 앱을 다시 실행해도 목록이 유지됩니다.

- 목록의 **연필** 아이콘을 누르면 그 자리에서 이름을 고칠 수 있습니다. Enter 로 저장하고 Esc 로 되돌립니다.
- **휴지통** 아이콘은 확인을 거쳐 그 화풍만 지웁니다. 이미 적용된 설정, 기존 프로젝트와 생성 이미지는 유지됩니다.
- 기존 프로젝트의 화풍이나 수정한 태그·네거티브·생성 설정은 「현재 설정을 새 화풍으로 저장」으로 보관합니다. 이름을 물어보며, 고른 화풍을 덮어쓰지 않고 새 항목을 만듭니다.

저장 항목은 화풍 프롬프트, 공통 네거티브, 참고 파일명, CFG·리스케일·스텝·샘플러·시드·V5 모델입니다. 자동 추출 때 기록되지 않은 옵션은 저장하지 않으며 다시 적용할 때 현재 값을 유지합니다. **해상도는 저장하거나 적용하지 않습니다.** 이미지 원본과 계정 정보도 화풍 목록에 포함되지 않습니다.

화풍 데이터는 `plugins/manga-maker/_data/styles.json`에 저장되며 프로젝트마다 적용된 설정의 사본을 따로 보관합니다. 플러그인을 업데이트할 때 `_data` 폴더를 보존하세요.

## 컴팩트한 화면 (1.1.1)

자주 쓰는 것을 위로 올리고 나머지는 접어, 왼쪽 패널과 편집창을 다시 짰습니다.

- **패널 맨 위가 「이번에 그릴 내용」입니다.** 그 아래에 기획 LLM, 맨 아래에 설정 탭을 둡니다. 자주 쓰는 순서대로 위에서 아래입니다.
- **기획 LLM은 늘 보입니다.** 입력 칸 바로 아래에 공급자·모델·추론 강도가 고정으로 있고, 고르는 즉시 저장되어 「LLM 설정 저장」 버튼이 없어졌습니다. 「목록 새로고침」이 공급자와 모델 목록을 함께 다시 받습니다.
- **설정은 탭 넷입니다.** 구성·화풍·생성·저장을 탭으로 나눠 한 번에 한 묶음만 보여 주고, 마지막으로 연 탭을 기억합니다. 접이식 묶음 다섯과 화면의 설명 문단은 없앴습니다.
- **「이번에 그릴 내용」 한 칸이 기획과 이어서 그리기를 겸합니다.** 새 만화든 이어서 그리든 같은 칸에 적고 장수를 고른 뒤 「콘티 생성」 또는 「콘티 + 이미지 생성」을 누릅니다. 기획이 아직 남아 있으면 같은 버튼이 남은 페이지를 잇습니다. 보낸 뒤 칸은 비워집니다.
- **「이 이야기로 전체 다시 기획」은 없앴습니다.** 처음부터 다시 만들려면 상단의 「새 만화」를 누릅니다. 기존 프로젝트를 열어도 이야기 칸이 덮이지 않고, 다음에 그릴 내용을 받는 자리로 비어 있습니다.
- **패널이 화면에 붙어 있습니다.** 긴 콘티를 스크롤해도 탭과 입력 칸이 제자리에 남고, 탭 안의 설정만 따로 스크롤됩니다.
- **화풍은 고르면 곧 적용됩니다.** 「선택한 화풍 적용」 버튼을 없앴고, 이름 변경과 삭제는 목록 항목 안의 아이콘 버튼으로 옮겼습니다. 이름 칸도 목록 안에서 바로 고칩니다. 화풍을 골라도 보던 탭에 그대로 머뭅니다(전에는 생성 탭으로 넘어갔습니다).
- **화풍 탭 차례를 바꿨습니다.** 화풍 선택 → 내 화풍(고르는 칸) → 참고 이미지 가져오기 → 공통 화풍 프롬프트 → 공통 네거티브 → 「현재 설정을 새 화풍으로 저장」 순입니다.
- **「화풍 선택」 한 칸으로 정합니다.** 흑백 만화 · 컬러 만화 · 내 화풍 셋 중 고릅니다. 구성 탭에 있던 「그림」과 「참고 화풍 사용」 체크박스를 합친 것입니다. 화풍 프롬프트에 무언가 적거나 저장된 화풍을 고르면 자동으로 「내 화풍」이 되고, 프롬프트를 비우면 흑백/컬러 기본 태그로 돌아갑니다.
  - 흑백: `monochrome, screentones, hatching (texture)` · 컬러: `full color comic, anime coloring`. 둘 다 품질 태그가 함께 붙습니다. 「내 화풍」은 이 자리를 화풍 프롬프트로 통째로 바꾸므로 필요한 품질 태그도 프롬프트에 함께 적습니다.
- **편집창은 모든 칸에 왼쪽 라벨이 붙었습니다.** 페이지·재기획·장면 태그가 맨 위, 그 아래 컷 카드입니다. 컷 카드는 머리줄에 번호·테두리·좌표를 요약하고 「영역」을 눌러야 좌표 칸이 펼쳐집니다. 인물마다 카메라·동작·표정·컷 안 위치가, 대사는 화자와 한 줄에 놓입니다. 페이지 삭제는 페이지 줄의 아이콘 버튼입니다.

## 레퍼런스 형식의 프롬프트 (1.1.0)

사용자가 준 레퍼런스 25장의 프롬프트를 다시 분석해 컴파일러와 기획 지침을 그 형식으로 바꿨습니다. 레퍼런스는 베이스가 태그만이고(영어 문장 0/25), `comic`·`dynamic angle` 25/25, `multiple views` 23/25, 인물 슬롯도 태그만이며(131개 중 문장 0) `from side`·`face focus` 같은 카메라 태그가 앞에 옵니다. 1.0.x는 베이스에 페이지 구성 문장과 읽는 방향 문장을, 슬롯에 "Panel 1, top right only" 같은 문장과 장면 문장을 넣었는데, 그 결과가 컷 구성이 아니라 일러스트 나열처럼 나왔습니다.

- **베이스:** 화풍·품질 태그(흑백은 `monochrome, screentones, hatching (texture)`) + `multiple views, comic, manga, dynamic angle`(한 컷 페이지는 multiple views 제외, 왼→오 읽기는 `left-to-right manga` 추가) + 페이지 장면 태그 + 인물 수 + 대사 언어 태그. 문장은 없습니다.
- **인물 슬롯:** `girl, 카메라 태그, 공유 외형, 동작·표정 태그[, small panels|inset panels][, 컷 고유 장면 태그], speech bubble, "대사"`. 컷 영역이 페이지의 15% 이하이면 `small panels`, 겹치는 컷이면 `inset panels`를 코드가 붙입니다. 내레이션은 `no humans, narration box, "…"`, 인물 없는 컷은 `no humans, 장면 태그`입니다.
- **기획 지침:** 모든 프롬프트 칸을 단부루 태그로만 쓰게 하고, 페이지 장면 태그(`setting`)와 인물마다 카메라 태그(`camera`)를 새로 받습니다. 「페이지 전체 구성」 문장은 더 이상 만들지 않고 모델에도 보내지 않습니다.
- **상세 지시 모드 제거:** 「프롬프트 구성」 선택이 없어지고 모든 페이지가 이 형식으로 컴파일됩니다. 기존 프로젝트는 그대로 열리며 다음 생성부터 새 형식이 적용됩니다. 기존 콘티의 문장형 장면·동작은 그대로 슬롯에 실리므로, 태그 형식으로 바꾸려면 「이 페이지 다시 기획」을 누르세요.
- **편집기:** 페이지에 「페이지 장면 태그」, 인물마다 「카메라 태그」·「동작·표정 태그」, 컷에 「컷에만 있는 장면 태그」 칸이 있습니다.
- **고정 시드:** 시드를 정하면 모든 페이지에 같은 값을 씁니다. 무작위(-1)일 때만 페이지마다 달라집니다.
- **기획 답이 JSON이 아닐 때:** 오류 메시지에 모델이 실제로 보낸 답의 앞 200자를 함께 보여 줍니다. 산문 거부인지 형식 문제인지 그 자리에서 보입니다. JSON 앞뒤에 설명이 붙은 답은 첫 `{ … }` 블록만 읽어 그대로 진행합니다.
- **페이지 삭제:** 편집기의 「이 페이지 삭제」로 그 페이지의 콘티와 이미지 목록을 지웁니다. 생성된 파일은 워크스페이스에 남습니다. 마지막 한 페이지는 지울 수 없고, 지운 뒤 「이어서 그리기」로 그 자리부터 새로 만들 수 있습니다.
- **읽는 순서 보정:** 자유 배치에서 LLM이 마지막 줄을 왼쪽→오른쪽으로 놓는 일이 있어(오른쪽부터 읽기인데 5번이 왼쪽, 6번이 오른쪽), 기획 결과를 받을 때 코드가 읽는 순서를 검사해 어긋나면 컷 영역을 이야기 순서에 맞게 다시 배정합니다. 위→아래, 같은 높이는 오른쪽→왼쪽(왼쪽부터 읽기면 반대), 세로로 쌓인 컷은 위에서 아래로 먼저 읽는 규칙이며, 컷의 내용은 그대로이고 영역만 바뀝니다. 직접 편집한 영역은 건드리지 않습니다.

## 기획 중 생성과 이어서 그리기 (1.0.9)

기획이 아직 진행 중이어도 콘티가 끝난 페이지는 바로 생성할 수 있습니다. 페이지 탭에서 고르고 「이 페이지 생성」을 누르면 생성 대기에 들어가고, 기획은 멈추지 않고 다음 페이지로 넘어갑니다. 「기획되는 대로 생성」을 누르면 이후 페이지도 콘티가 끝나는 대로 차례로 생성합니다. 상태 카드에 기획 진행과 생성 진행이 함께 표시되며, 기획 중에 만든 이미지는 「멈추기」를 눌러도 남습니다.

「이어서 그리기」는 현재 만화의 마지막 페이지 뒤를 이어 새 페이지를 기획합니다. 추가 페이지 수는 자동(1~8장, LLM이 정함) 또는 1~8장 중 고르고, 「이어질 내용」은 비워 두면 앞 내용에서 자연스럽게 이어집니다. 「이어서 기획」은 콘티까지, 「이어서 기획하고 생성까지」는 새 페이지의 이미지까지 만듭니다. 기존 페이지와 이미지는 그대로이고, 새 페이지의 컷·대사도 다른 페이지처럼 수정하거나 다시 기획할 수 있습니다. 한 만화는 모두 40페이지까지이며, 기획이 끝난 뒤에만 이어서 그릴 수 있습니다. 새 등장인물은 추가하지 않고 기존 캐릭터 설정 안에서 이어집니다.

기존 작품의 캐릭터를 이야기에 쓰면 캐릭터 설정 프롬프트가 그 캐릭터의 단부루 캐릭터 태그와 작품(저작권) 태그로 시작합니다. 이 태그가 있어야 NAI가 그 캐릭터를 그립니다. 1.0.8까지는 태그가 불확실하면 외형 묘사로 대신하도록 되어 있어 태그가 빠지는 일이 있었습니다.

## 추론 강도와 대사 프롬프트 (1.0.8)

「만화 기획 LLM」의 모델과 추론 강도는 앱 설정 화면(AI 조수)과 같은 드롭다운입니다. 공급자를 고르면 모델 목록을 자동으로 불러오고, 추론 강도는 그 모델이 알려 준 단계만 보여 줍니다. CLI는 max·xhigh·high·medium·low 중 고르며 기본은 high, API의 「모델 기본값」은 강도를 보내지 않습니다. 이 선택은 앱의 조수 설정과 별개로 저장됩니다. 1.0.7까지는 API 강도를 항상 비워 보냈고, CLI는 사용자 전역 설정의 강도를 물려받았습니다.

CLI 기획은 이제 설정 원본을 읽지 않고 실행합니다(`--setting-sources ""`). 이전에는 작업 폴더 위의 `CLAUDE.md`와 사용자 메모리·출력 스타일이 페이지마다 요청에 실렸습니다. 2026-09-14 측정에서 같은 페이지 요청의 입력이 128,740토큰에서 8,284토큰으로 줄었고, opus의 페이지당 시간은 xhigh 105~120초, low 25초, CLI 기본 43초였습니다.

대사는 인물 슬롯과 베이스의 따옴표 안에만 두고, 플러그인이 베이스 끝에 직접 쓰던 `Text:` 블록을 없앴습니다. 호스트가 따옴표 대사를 모아 `teXt:` 블록을 한 번 만들기 때문에, 직접 쓴 블록은 같은 대사를 두 번 싣는 결과였습니다. 이미 생성한 이미지는 그대로이며 다음 생성부터 적용됩니다.

## 참고 이미지의 생성 옵션 (1.0.5)

참고 이미지를 가져오면 화풍·네거티브와 함께 **CFG, 가이던스 리스케일, 스텝, 샘플러, 시드, 명시된 V5 모델**을 적용합니다. 숫자는 LLM이 추측하지 않고 메타데이터에서 직접 읽습니다. 가져온 항목은 이미지 아래에 나열되며 「이미지 생성 설정」에서 바로 수정할 수 있습니다.

기록되지 않은 값은 현재 설정을 유지합니다. 0인 CFG·리스케일·시드도 보존합니다. 지원하지 않는 모델·샘플러나 범위를 벗어난 값은 적용하지 않고 항목을 표시합니다. 고정 시드는 1.1.0부터 모든 페이지에 같은 값을 씁니다(1.0.x는 페이지마다 1씩 증가).

**만화의 기본 해상도는 832×1216입니다.** 1.0.5부터 참고 이미지의 해상도는 가져오지 않으며 현재 페이지 크기를 유지합니다. 크기를 바꾸려면 「이미지 생성 설정 → 페이지 크기」에서 프리셋을 선택하거나 가로·세로를 64 배수로 직접 입력하세요. 이전 버전에서 변경된 크기를 기본으로 되돌릴 때도 「832 × 1216 (기본)」을 선택합니다. 저장된 프로젝트의 크기는 자동으로 덮어쓰지 않습니다.

V5의 스케줄러는 호스트 요청 조립기에서 Karras로 고정됩니다. V5가 지원하지 않는 Variety+·SMEA, 원본의 인페인트·참조 이미지 입력은 복사하지 않습니다. 생성 옵션 변경은 다음 생성에 반영되며 이전 이미지는 보관됩니다.

## 작업 표시와 큰 이미지 보기 (1.0.4)

- 작업 중에는 회전 표시, 강조된 상태 카드, 작업 단계, 경과 시간이 표시됩니다. 여러 페이지 작업은 실제 완료 페이지 수를 표시하며, NAI 큐 대기도 구분합니다. 개별 LLM 응답 시간이나 생성 스텝 진행률을 추정한 숫자는 표시하지 않습니다.
- 참고 이미지 가져오기와 모델 목록 불러오기 등도 해당 영역·버튼에 움직이는 표시가 생깁니다. 1.0.6부터 중단하면 응답 완료를 기다리지 않고 이전 기획을 즉시 표시합니다.
- 「생성 이미지」는 본문 전체 너비를 사용하며 편집창은 아래로 이동합니다. 「보기 너비」 슬라이더로 320~2000px 범위에서 조절하거나 「화면에 맞춤」을 선택합니다. 창보다 넓게 설정하면 창 너비에 맞추며 실제 표시 너비를 함께 보여 줍니다. 이미지 클릭으로 원본도 열 수 있습니다.
- 이야기·화풍·생성 옵션·저장 위치·LLM 설정을 각각 접고 펼칠 수 있습니다. 왼쪽 「설정 접기」와 「편집창 접기」로 이미지 공간을 더 넓힐 수 있습니다. 너비와 접힘 상태는 이 브라우저에 저장됩니다.

## 작업 중 대사 언어 변경 (1.0.3)

새 기획의 기본 대사 언어는 한국어입니다. 기존 프로젝트는 저장된 언어를 유지하며, 작업이 실행 중이지 않을 때 언어를 바꿀 수 있습니다.

언어 선택은 이후 기획과 문자 프롬프트에 적용됩니다. 이미 작성된 대사까지 바꾸려면 「기존 대사를 선택한 언어로 번역」을 누르세요. 선택한 LLM이 프로젝트의 기존 대사 전체를 번역하며 컷 수·배치·화자·장면을 유지합니다. 모든 페이지 번역을 검증한 뒤 한 번에 적용하므로 중단·실패하면 기존 대사가 남습니다. 이전 콘티는 `plan_history`에 보관합니다.

「대사 없음」은 저장된 대사를 지우지 않고 생성 프롬프트와 편집 화면에서만 숨깁니다. 언어를 다시 선택하면 대사가 나타납니다. 처음부터 대사 없는 콘티였다면 번역할 내용이 없으므로 재기획하거나 대사를 직접 추가합니다. 이미 생성된 이미지의 글자는 변경되지 않으며 「이 페이지 생성」으로 다시 생성해야 새 대사가 반영됩니다.

## 만화 전용 LLM과 CLI

만화 기획용 공급자·모델은 `_data/llm.json`에 별도로 저장됩니다. 앱의 현재 채팅 모델을 바꾸지 않습니다. 「앱 API 설정 따르기」는 앱의 API 설정을 사용하는 선택이며 현재 채팅의 CLI 선택을 자동으로 가져오는 의미가 아닙니다.

- CLI 설치 뒤 「설정 새로고침」으로 다시 탐지합니다. OpenCode는 현재 이 플러그인의 기획 실행을 지원하지 않습니다.
- 모델은 공급자를 고르면 자동으로 불러온 목록에서 선택합니다. CLI 모델을 비워 두면 해당 CLI의 기본 모델을 사용합니다. API는 명시적인 모델이 필요합니다.
- 기획을 시작할 때 설정을 저장하고 그 기획의 모든 요청에 같은 선택을 사용합니다. 오류 후 「기획 이어서」에는 새로 선택한 LLM을 사용할 수 있습니다.
- CLI는 현재 채팅 세션과 별개의 일회성 텍스트 요청으로 실행합니다. 한 요청의 제한 시간은 10분입니다. CLI 설치 여부가 로그인·모델 사용 권한까지 보장하지는 않습니다.

실행 형식은 [Codex 비대화형 실행 문서](https://developers.openai.com/codex/noninteractive/)와 [Claude Code CLI 문서](https://code.claude.com/docs/en/cli-reference), 설치된 실행 파일의 도움말을 대조했습니다.

## 자유 배치와 기존 4컷 콘티 바꾸기 (1.0.2)

1.0.1은 프롬프트 슬롯 구성만 개선했으며, 콘티는 여전히 고정 템플릿·기본 최대 4컷에 묶여 있었습니다. 1.0.2는 기획 스키마와 편집기까지 변경했습니다.

- LLM이 컷마다 페이지 좌표 `x,y,w,h`와 전체 페이지 구성 설명을 직접 작성합니다. 자유 배치 요청에 고정 템플릿으로 답하면 수정 요청을 보냅니다.
- 크기가 다른 사각 컷, 세로 컷, 사선 컷, 테두리 없는 큰 그림, 겹치는 작은 컷을 조합할 수 있습니다. 사선 컷 안의 인물 좌표도 기울기에 맞게 변환합니다.
- 컷 수 자동은 1~12 범위에서 정합니다. 페이지당 위치 슬롯 22개와 문자 예산은 유지합니다. 둘은 컷 수와 다른 제한입니다.
- 자유 배치 프롬프트는 전체를 균일한 검은 테두리로 나누라는 문구를 붙이지 않습니다. 전체 구성 설명과 지역 슬롯을 사용합니다.
- 자유 배치의 목록 순서는 이야기 순서입니다. 영역을 자동 정렬하거나 읽는 방향을 바꿀 때 뒤집지 않습니다. 방향에 맞춰 배치 자체를 다시 설계하려면 재기획을 사용합니다.

기존 프로젝트는 **컷 구성 방식 → 자유 배치**, **페이지당 최대 컷 → 자동**으로 바꾼 뒤 해당 페이지의 **「이 페이지 다시 기획」**을 누르세요. 현재 LLM 선택과 설정으로 컷 수·크기·구성을 새로 정합니다. 이전 콘티는 프로젝트 JSON의 `plan_history`에, 이미지는 기존 버전 목록에 보관됩니다. 실패하면 기존 콘티도 유지됩니다. 새 콘티의 이미지 생성은 「이 페이지 생성」으로 실행합니다.

기존 템플릿을 편집기의 「컷 배치 → 자유 배치」로 바꾸면 같은 위치를 유지한 채 크기 편집을 시작합니다. 이 변환 자체가 AI 재기획은 아닙니다.

## 원본 프롬프트에서 반영한 구성

사용자가 제공한 25개 PNG의 숨겨진 NAI 메타데이터를 호스트 리더로 읽고, 장면 내용 대신 좌표 슬롯과 문자 처리 구조를 분석했습니다. 수치와 차이는 [원본 프롬프트 분석 기록](docs/reference-prompt-analysis.md)에 있습니다.

1.0.1~1.0.9의 「좌표 중심」·「상세 지시」 두 방식은 1.1.0에서 레퍼런스 형식 하나로 합쳐졌습니다(위 「레퍼런스 형식의 프롬프트」). 이전 이미지 버전은 그대로 보관합니다.

## 저장과 중단

- 기획: `plugins/manga-maker/_data/projects/<id>.json`. 플러그인 업데이트 시 `_data`를 보존하는 PeroPix 규격을 따릅니다.
- 이미지: 선택한 워크스페이스의 `output/` 아래, `만화 제작기` 탭 이름과 프로젝트 이름을 사용합니다. 실제 경로는 이미지 아래에 표시됩니다. 결과 조회는 이 플러그인과 앱의 파일 탐색기를 이용합니다. 기존 프롬프트 카드나 씬 구성은 수정하지 않습니다.
- 재생성은 새 파일을 만듭니다. 이전 이미지를 덮어쓰거나 삭제하지 않습니다.
- **「멈추기」는 즉시 현재 기획·재기획·번역 요청을 취소합니다.** 이번 실행에서 작성 중이던 내용을 버리고 시작 전 상태로 돌아갑니다. 만화 기획용 CLI 프로세스와 그 자식 프로세스도 종료합니다. 취소된 요청이 늦게 응답해도 결과를 적용하지 않으며, 즉시 다른 작업을 시작할 수 있습니다.
- 이미지 생성은 이번 플러그인의 대기 요청만 제거하고 현재 만화에 미완성 결과를 반영하지 않습니다. 이미 완료하여 반영된 이미지는 보존합니다. NAI로 이미 전송한 요청은 서버에서 회수할 수 없으므로 나중에 저장 폴더에 이미지가 남을 수 있습니다. 다른 작업의 큐를 비우거나 생성 파일을 삭제하지 않습니다.
- 창을 닫아도 백엔드가 켜져 있으면 작업은 계속됩니다. 앱이 종료되면 다음 실행에서 저장된 결과를 대조해 복원하고 사용자의 이어서 실행을 기다립니다. 완료 여부가 불명확한 유료 요청을 자동 재시도하지 않습니다.
- LLM의 잘못된 JSON은 한 번만 수정 요청합니다. NAI 생성 실패는 자동 재시도하지 않습니다. 기획에는 LLM 요금이, 이미지에는 NAI 사용량 또는 Anlas가 들 수 있습니다.

## 조사 결과와 구현 판단

2026-09-14에 확인한 1차 자료를 기반으로 했습니다. 상세 설계와 프롬프트 예시는 [NAI V5 조사 기록](docs/nai-v5-manga.md)에 있습니다.

- [V5 공식 발표](https://journal.novelai.net/image-generation-novelai-diffusion-v5-is-here-c2df7c6b8d2d/): 자연어로 컷 구성을 설명하고 인물 위치를 지정해 한 번에 만화 한 페이지를 생성할 수 있습니다.
- [멀티 캐릭터 문서](https://docs.novelai.net/en/image/multiplecharacters/): 베이스와 캐릭터 프롬프트를 분리하고, 위치와 자연어 설명을 함께 사용하는 방식을 반영했습니다.
- [텍스트 렌더링 문서](https://docs.novelai.net/en/image/textrendering/): 대사의 위치와 화자를 서술하고 대사는 따옴표로 적습니다. 1.0.8부터 `Text:` 블록은 플러그인이 쓰지 않고 호스트가 따옴표 대사를 모아 만듭니다. 문서의 최대치는 Full 750자, Curated 374자입니다. 제작기는 줄바꿈 포함 600자/300자로 여유를 두었습니다.
- [품질 태그](https://docs.novelai.net/en/image/qualitytags/)와 [네거티브 프리셋](https://docs.novelai.net/en/image/undesiredcontent/): `no text`, `screentone`, `multiple views`, `comic` 등과의 충돌을 피하려고 자동 프리셋을 끄고 만화용 품질 태그·네거티브를 직접 구성합니다.

인물 외형을 반복하고 각 컷의 등장을 별도 좌표 슬롯으로 만드는 것은 이 플러그인의 구성 전략입니다. 컷의 테두리를 강제로 자르는 마스크 방식은 아닙니다. 컷 분할, 대사 정확도, 인물의 페이지 간 동일성이 항상 보장되지는 않습니다. 영어·일본어가 공식 지원 언어이며 한국어 대사 결과는 불안정할 수 있습니다.
